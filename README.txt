=====================================================
  smm panel — شرح المشروع وطريقة التشغيل
=====================================================

أولاً: فكرة المشروع
-------------------
موقع خدمات تسويق (SMM Panel) بالعربي (RTL). الأدمن يدخل الخدمات والأسعار والمزودين من لوحة التحكم،
والعميل يشحن رصيده ويطلب ويتابع طلباته. كله مجاني (GitHub + Supabase + Render) ما عدا الدومين.

ثانياً: ملفات المشروع
---------------------
smm-panel/
├── index.html          الصفحة الوحيدة (هيكل HTML فقط)
├── style.css           كل التصميم + متغيرات الألوان (الثيم)
├── config.js           إعدادات عامة اختيارية (رابط Supabase والـ anon key ورابط الباك إند)
├── index-standalone.html  نفس الموقع في ملف واحد (للفتح من الموبايل أو بالضغط المزدوج). املأ بيانات Supabase في أول الملف (window.APP_CONFIG)
├── script.js           منطق الواجهة: الصفحة الرئيسية، لوحة العميل، لوحة الأدمن، الاتصال بـ Supabase
├── backend/
│   └── main.py         الباك إند (Python + FastAPI)
├── update_v2.sql       تحديث قاعدة البيانات (اسم مستخدم فريد، رفض الدفعات، تخزين اللوجو) — شغّله بعد schema.sql
├── schema.sql          قاعدة البيانات كاملة (جداول + صلاحيات RLS + دوال الرصيد والطلبات الآمنة)
├── requirements.txt    مكتبات بايثون
├── .env.example        نموذج متغيرات البيئة (بدون أسرار)
├── .gitignore          يمنع رفع .env
└── README.txt          هذا الملف

ثالثاً: إيه اللي بيعمله كل جزء
------------------------------
1) الواجهة (index.html + style.css + script.js)
   - الصفحة الرئيسية: مميزات، طريقة الاستخدام، جدول الخدمات (من قاعدة البيانات)، أسئلة شائعة، فوتر + 3 صفحات قانونية.
   - تسجيل الدخول وإنشاء الحساب (Supabase Auth).
   - لوحة العميل: الرصيد والإحصائيات، طلب جديد (حساب السعر تلقائياً والتحقق من الرصيد والحدود)،
     الخدمات، سجل الطلبات بالحالات السبع، شحن الرصيد + سجل المعاملات، تذاكر الدعم (مع الردود).
   - لوحة الأدمن: إحصائيات، إدارة الخدمات والتصنيفات، المزودون + مزامنة الطلبات، إدارة الطلبات
     (تغيير الحالة + استرداد)، قبول المدفوعات، المستخدمون (حظر + تعديل الرصيد بسبب إلزامي)، التذاكر،
     الثيم والإعدادات (اسم الموقع، اللوجو، الألوان، بيانات الدفع) بمعاينة مباشرة.

2) الباك إند (backend/main.py) — خدمة FastAPI واحدة بتقدّم الواجهة والـ API معاً:
   GET  /api/config          يرجّع رابط Supabase والـ anon key للمتصفح (مفتاح عام بطبيعته)
   POST /api/orders          ينشئ الطلب بدالة place_order (خصم آمن) ثم يرسله لـ API المزود
   POST /api/admin/provider  (أدمن فقط) يحفظ المزود ومفتاحه في جدول سري لا يقرأه المتصفح
   POST /api/admin/sync      (أدمن فقط) يجلب حالات الطلبات من المزودين ويرجّع رصيد الملغي/الجزئي
   * service_role key موجود في الخادم فقط، ولا يوصل للمتصفح أبداً.

3) قاعدة البيانات (schema.sql)
   - الجداول: profiles, wallets, categories, providers, provider_secrets, services, orders,
     transactions, payments, support_tickets, ticket_messages, coupons, settings, audit_logs.
   - الرصيد لا ينزل تحت صفر، وكل حركة لها رقم مرجعي فريد (يمنع تكرار الخصم/الإيداع).
   - سعر الخدمة يتحفظ داخل الطلب وقت الشراء.
   - المتصفح مش قادر يعدّل الرصيد أو الدفعات أو دور المستخدم مباشرة؛ كل ده بدوال على الخادم.

رابعاً: التشغيل خطوة بخطوة
--------------------------
(أ) Supabase
  1. ادخل supabase.com واعمل New Project (مجاني).
  2. من القائمة: SQL Editor -> New query -> الصق محتوى schema.sql كله -> Run.
     ثم New query تانية -> الصق محتوى update_v2.sql -> Run.
  3. Project Settings -> API: انسخ  Project URL  و  anon public key  و  service_role key.
  4. Authentication -> Providers -> Email: للتجربة السريعة عطّل "Confirm email".
     (لما تنشر: Authentication -> URL Configuration -> حط رابط Render في Site URL.)

(ب-0) مهم: ما تفتحش index.html بالضغط المزدوج وانتظر يشتغل لوحده.
  الصفحة محتاجة إعدادات Supabase. أسهل طريقة: شغّلها عبر الخادم (الخطوة ب).
  لو عايز تفتحها مباشرة: افتح ملف config.js واملأ supabaseUrl و supabaseAnonKey (anon فقط)،
  وللطلبات والمزودين املأ apiBase برابط Render بعد النشر. لو الإعدادات ناقصة هتظهر رسالة توضّح كده.

(ب) تشغيل على جهازك (اختياري للتجربة)
  1. ثبّت Python 3.11+.
  2. داخل مجلد المشروع:
        python -m venv venv
        source venv/bin/activate          (ويندوز: venv\Scripts\activate)
        pip install -r requirements.txt
  3. انسخ .env.example باسم .env وحط القيم التلاتة.
  4. شغّل:
        uvicorn backend.main:app --reload --env-file .env
  5. افتح http://127.0.0.1:8000

(ج) أول أدمن
  1. سجّل حساب عادي من الموقع.
  2. في Supabase -> SQL Editor شغّل (ضع بريدك):
        update profiles set role='admin' where id = (select id from auth.users where email='بريدك@example.com');
  3. حدّث الصفحة: هيظهر رابط "لوحة الأدمن" في القائمة الجانبية.

(د) الرفع على GitHub
        git init
        git add .
        git commit -m "smm panel"
        git branch -M main
        git remote add origin https://github.com/اسمك/smm-panel.git
        git push -u origin main
  (اعمل الـ repo خاص Private. ملف .env مستبعد تلقائياً.)

(هـ) النشر على Render (مجاني)
  1. render.com -> New -> Web Service -> اربط حساب GitHub واختر الـ repo.
  2. الإعدادات:
        Runtime:        Python 3
        Build Command:  pip install -r requirements.txt
        Start Command:  uvicorn backend.main:app --host 0.0.0.0 --port $PORT
        Instance Type:  Free
  3. Environment -> أضف المتغيرات:  SUPABASE_URL  و  SUPABASE_ANON_KEY  و  SUPABASE_SERVICE_KEY
  4. Deploy. هيدّيك رابط زي  https://smm-panel.onrender.com  (حطه في Site URL في Supabase).
  * أي push جديد على GitHub بيتنشر تلقائياً.

خامساً: ترتيب الاستخدام بعد النشر
---------------------------------
1. لوحة الأدمن -> الخدمات: أضف تصنيف (مثلاً Instagram) ثم أضف الخدمات بأسعارها وحدودها.
2. لو هتشتغل مع مزود: المزودون -> أضف الاسم ورابط الـ API والمفتاح، وبعدين اربط كل خدمة بالمزود
   وبرقم الخدمة عنده (Service ID). الخدمة من غير مزود = تنفيذ يدوي (الأدمن يغيّر الحالة بنفسه).
3. الثيم والإعدادات: اكتب بيانات الدفع (رقم فودافون كاش مثلاً) واضغط حفظ.
4. العميل يطلب شحن -> الأدمن يراجع التحويل من "المدفوعات" -> "قبول وشحن".
5. من "المزودون" اضغط "مزامنة الآن" كل فترة لتحديث حالات الطلبات.

سادساً: ملاحظات وحدود مهمة (اقرأها)
-----------------------------------
- Render المجاني بينام بعد حوالي 15 دقيقة بدون زوار، وأول زيارة بعدها بتاخد وقت للتشغيل.
- Supabase المجاني بيتوقف لو مفيش نشاط حوالي أسبوع (تفتحه من لوحته).
- لو الاتصال بالمزود فشل أو انقطع أثناء الإرسال، الطلب يفضل Pending مع كتابة الخطأ ولا يُعاد
  إرساله تلقائياً (عشان ما يتنفذش مرتين). الأدمن يراجع الطلب عند المزود ويحدّث حالته.
- نصوص الصفحات القانونية في script.js (كائن LEGAL) نصوص مبدئية قصيرة؛ لازم تعدّلها وتراجعها قبل الإطلاق.
- لا تضع service_role key في أي ملف يُرفع على GitHub.

سابعاً: اللي لسه مش موجود (تحب نكمله لاحقاً)
--------------------------------------------
- الكوبونات والإحالة: الجداول موجودة في قاعدة البيانات لكن لا توجد صفحات ولا منطق لها بعد.
- بوابات دفع آلية (Paymob/Fawry): حالياً الشحن يدوي بمراجعة الأدمن.
- رفض دفعة (Reject) من الأدمن، وإشعارات داخل الموقع والبريد، واستعادة كلمة المرور.
- التقارير والتصدير، وعرض سجل العمليات (audit_logs موجود ويُسجَّل فيه فعلاً).
- المصادقة الثنائية للأدمن (متاحة من Supabase Auth لكنها غير مفعّلة في الواجهة).
- نسخ احتياطي تلقائي (الخطة المجانية لا تضمنه): الحل المقترح GitHub Actions يعمل pg_dump أسبوعي.
- اختبارات آلية، وجدولة المزامنة تلقائياً بدل الزر.
- آراء العملاء: لم أضع آراء وهمية؛ تضاف عندما تتوفر آراء حقيقية.


ثامناً: تحديث v2 (اللغة، الدخول باسم المستخدم، الهوية)
------------------------------------------------------
- اللغة: العربية هي الأساسية (RTL). زر EN / عربي في الهيدر وصفحات الدخول وفي القائمة الجانبية يبدّل للإنجليزية
  (LTR) ويتذكر اختيار الزائر. اللغة الافتراضية للموقع يحددها الأدمن من الإعدادات.
  لإضافة/تعديل ترجمة: القاموس موجود في script.js (سطر لكل جملة بصيغة  عربي=English).
- الرجوع: في صفحتي تسجيل الدخول وإنشاء الحساب فيه زر "الرجوع للموقع".
- الدخول: العميل يدخل باسم المستخدم أو بالبريد + كلمة المرور. اسم المستخدم فريد (3-20 حرف إنجليزي/أرقام/_).
  تحويل اسم المستخدم لبريد بيحصل على الخادم (/api/login) فمفيش حد يقدر يعرف بريد حد.
- الخصوصية: كلمات المرور بتتخزن مشفّرة (hash) داخل Supabase Auth ولا يمكن لأحد قراءتها، ولا حتى الأدمن.
  كل عميل يشوف حسابه وطلباته ومحفظته ومعاملاته وتذاكره فقط (قواعد RLS في قاعدة البيانات).
  العميل يغيّر كلمة مروره من صفحة "حسابي".
- لوحة الأدمن -> الثيم والإعدادات (صاحب الموقع يعدّل كل ده بدون كود): ألوان جاهزة (6 ثيمات) + ألوان مخصصة،
  استدارة الزوايا، اسم الموقع بالعربي والإنجليزي، لوجو إيموجي أو صورة مرفوعة، عنوان ووصف الصفحة الرئيسية
  بلغتين، واتساب وتيليجرام وبريد التواصل، بيانات الدفع. المعاينة مباشرة والحفظ يطبّق على كل الزوار.
- لوحة الأدمن الجديدة: سجل العمليات، ورفض الدفعات.
- لا يوجد حدّ لمحاولات تسجيل الدخول على /api/login حالياً؛ أضف حماية (rate limit) قبل الإطلاق التجاري.


تاسعاً: لو ظهرت شاشة بيضاء أو رسالة خطأ
----------------------------------------
- الصفحة دلوقتي مش بتفضل بيضاء: لو حصل خطأ بتكتب سببه على الشاشة (تعذّر تشغيل الموقع + السطر). ابعت السطر ده للمطوّر.
- الأسباب الشائعة:
  1) فتح index.html من مدير ملفات الموبايل: الملفات الجانبية (script.js وstyle.css) ما بتتحمّلش. استخدم
     index-standalone.html (ملف واحد) أو افتح الموقع من رابط Render.
  2) ملف config.js فاضي وانت فاتح الملف مباشرة: املأ supabaseUrl وsupabaseAnonKey.
  3) الإنترنت أو مانع إعلانات حاجب لـ cdn.jsdelivr.net (مكتبة Supabase): جرّب شبكة تانية أو عطّل المانع للموقع.
  4) لم تشغّل schema.sql وupdate_v2.sql في Supabase: الصفحة تفتح لكن الخدمات والتسجيل مش هتشتغل.
